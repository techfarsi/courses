در JavaScript خطاها وقتی خودشان را نشان می‌دهند که برنامه اجرا شده و به آن خط رسیده. گاهی روی سیستم خودتان، گاهی وقتی کاربر از آن استفاده می‌کند.

TypeScript همان JavaScript است با یک اضافه: شما می‌گویید هر مقدار قرار است چه چیزی باشد، و ابزار قبل از اجرا بررسی می‌کند که کد با آن حرف جور در می‌آید یا نه.

<Callout type="info">
هر کد JavaScript که تا اینجا نوشته‌اید، کد معتبر TypeScript هم هست. چیز جدیدی برای یاد گرفتن از صفر نیست، فقط چند نشانه به کدی که بلدید اضافه می‌شود.
</Callout>

## نصب

در یک پروژه که از قبل با `pnpm init` ساخته‌اید:

```bash
pnpm add -D typescript tsx @types/node
```

سه چیز نصب شد:

- `typescript`: خود ابزار بررسی type ها
- `tsx`: اجرا کننده فایل‌های ts، بدون اینکه لازم باشد مرحله جدا برای تبدیل کد اجرا کنید
- `@types/node`: توضیح type های خود Node.js، تا TypeScript بداند چیزهایی مثل `process` چه شکلی هستند

علامت `-D` یعنی این‌ها ابزار کارند و بخشی از برنامه نهایی نیستند.

## فایل tsconfig.json

این فایل تنظیمات TypeScript برای پروژه است. بسازیدش و این را داخلش بگذارید:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "nodenext",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "skipLibCheck": true
  }
}
```

مهم‌ترین خط `"strict": true` است. بدون آن، TypeScript خیلی از مشکلات را نادیده می‌گیرد و شما زحمت نوشتن type ها را می‌کشید بدون اینکه سودش را ببرید.

خط `noUncheckedIndexedAccess` هم اضافه‌ای است که ارزشش را دارد: به TypeScript می‌گوید وقتی از یک array خانه‌ای را می‌خوانید، ممکن است آن خانه اصلا وجود نداشته باشد. این دقیقا همان حالتی است که در برنامه واقعی باعث خطا می‌شود.

## اولین فایل

فایلی به اسم `main.ts` بسازید:

```ts
const name: string = 'علی';

console.log(`سلام ${name}`);
```

اجرا کنید:

```bash
pnpm tsx main.ts
```

خروجی همان چیزی است که انتظار دارید. بخش `: string` یعنی «این متغیر همیشه یک متن است».

## دیدن خطا قبل از اجرا

حالا عمدا اشتباه کنید. این خط را اضافه کنید:

```ts
const age: number = 'سی';
```

ادیتور بلافاصله زیر آن خط قرمز می‌کشد و می‌گوید مقداری از نوع string را نمی‌شود در متغیری از نوع number گذاشت. هنوز هیچ چیزی اجرا نشده.

برای بررسی کل پروژه یک‌جا:

```bash
pnpm tsc --noEmit
```

`--noEmit` یعنی «فقط بررسی کن، فایل خروجی نساز». همین دستور است که بعدا در CI اجرا می‌شود تا کد خراب وارد پروژه نشود.

## تمرین

در `package.json` یک script به اسم `check` بسازید که بررسی type ها را اجرا کند، بعد آن را صدا بزنید.

<Solution>

در `package.json`:

```json
{
  "scripts": {
    "check": "tsc --noEmit"
  }
}
```

بعد:

```bash
pnpm check
```

اگر خط `const age: number = 'سی'` هنوز در فایل باشد، خطا را می‌بینید. آن را پاک کنید و دوباره اجرا کنید تا بدون خروجی تمام شود.

در خط فرمان، «بدون خروجی» یعنی همه چیز درست است.

</Solution>
